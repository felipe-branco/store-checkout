# Decisions

Brief notes for the take-home. Expand when needed.

- **Why this stack:** Event sourcing fits persisted orders and auditability; the repo started from an EM + vertical-slices starter, so the take-home is modeled in [Event Modelers](https://app.eventmodelers.ai/) instead of ad-hoc CRUD.
- **EM board:** **MashginCheckout** — canonical snapshot **`20260930011438_store`** (`manifest.json` → `currentSnapshot`). Re-import the matching JSON from `packages/em-manager/migrations/` in [Event Modelers](https://app.eventmodelers.ai/). Older snapshots are historical (`20260929200131_store` without cart `price_in_cents`; `20260929231730_store` before Dereserve “sold line” spec). After export, merge **`sliceStatus`** from repo `slice.ref.json` / prior migration so borders stay **Done** where implemented. Slice list: [EVENT_MODEL.md](./EVENT_MODEL.md).
- **UI / theme:** Kiosk UX from [Vercel v0](https://v0.dev); source archive [vercel-v0-self-service-store-theme-source.zip](./vercel-v0-self-service-store-theme-source.zip). Implemented in `@store-checkout/ui` (Tailwind 4 + shadcn tokens, kiosk components, mustard/charcoal palette).
- **Persistence:** orders, carts, and stock as domain events (PostgreSQL / Emmett). **Read models** are **materialized PostgreSQL tables** (Pongo collections, e.g. `cartdetails-collection`) updated on **each new event** via inline projections; menu availability uses those tables plus static catalog. Money/timestamps: [EVENT_SOURCING_BEST_PRACTICES.md](../EVENT_SOURCING_BEST_PRACTICES.md). Table layout and rebuild: [PROJECTION_REBUILD_PLAN.md](../PROJECTION_REBUILD_PLAN.md).
- **Menu / stock (no DB seed):** static catalog in `apps/web-app/src/lib/kiosk/product-catalog.ts`. Kiosk **`stock`** badges come from **`GET /api/products`** (`available = quantity − reserved − sold` via **Stock Products List** projection). **Stock commands** take **`on_hand_quantity`** from the static catalog at dispatch time.
- **Cart line price:** **`price_in_cents`** on **Add Item to Cart** / **Remove Item from Cart** commands and on **Item Added to Cart** / **Item Removed from Cart** events (snapshot `20260929231730_store`). Filled from static catalog at API dispatch; persisted on the cart stream for audit and future order/payment slices. **Cart Details** read model still merges lines by `item_id` + `quantity` only; kiosk totals use live catalog prices until order slices consume event prices.
- **Cart ↔ stock (API):** `POST`/`DELETE` `/api/cart/items` run **`ReserveStockItem` → `AddItemToCart`** and **`DereserveStockItem` → `RemoveItemFromCart`** (same `correlationId`). Stock step failure returns **409** and is logged via `withLoggedApiRoute` (`failedCommandType`, `errorCode`). Failed cart step after a successful stock step rolls back with dereserve / re-reserve. **`POST /api/cart/clear`** emits **`CartCleared`** only; **Cart Cleared Automator** dereserves via **`RemoveItemFromCart`** orchestration and **`ClearedCartItems`** projection.
- **Dereserve after sell:** EM spec — given **`StockItemSold`**, **`DereserveStockItem`** must not emit **`StockItemDereserved`**. Implemented in stock deciders (`soldByCartItem` guard + reservation consumed on sell) so checkout-then-clear does not double-touch sold lines.
- **Payment:** simulated only; no real gateway; no card data in events or logs.
- **UX:** self-service kiosk at `/`; English (`en-US`). **Local dev:** no login. **Production:** optional static access code + HttpOnly session cookie when `KIOSK_ACCESS_MAGIC_WORD` is set (see below) — not end-user accounts.
- **Kiosk client refresh (no WebSockets v0.1):** **Menu / availability** — `OrderScreen` loads `GET /api/products` via SWR (`packages/ui/src/hooks/use-products.ts`): **`refreshInterval` 15s**, **`revalidateOnFocus`**, `keepPreviousData`, so multi-kiosk or background stock changes eventually show up without a full reload. **Cart** — no polling: `CartDetails` fetches `GET /api/cart` on mount and after each add/remove/clear; home `/` probes cart once on mount for start vs order. Reserve/dereserve on add/remove updates the stock projection; menu polling helps other kiosks see availability without reload.
- **Local bootstrap:** root [Makefile](../Makefile) — `make setup` (deps, env, Postgres, `pnpm install`); Node **24+** enforced via `make check-deps` and `package.json` engines. Details: [LOCAL_SETUP.md](../LOCAL_SETUP.md).
- **API logging:** App Router routes use `@/lib/api-log` (`withLoggedApiRoute`) — structured stdout (+ optional Axiom); `correlationId`, timing, status; no card data in logs.
- **Production kiosk gate:** With **`KIOSK_ACCESS_MAGIC_WORD`** in production, users enter a static access code once; the server sets an **HttpOnly** signed **`kiosk_session`** cookie. Middleware blocks **`/api/*`** (except health, kiosk access/session, payment webhook) without a valid cookie — no secret in client JS. Local dev omits the env var so the gate is off.
- **Projections rebuild:** five inline Pongo collections (`CartDetails`, `StockProductsList`, `PaymentFailedOrder`, `OrderFinishedDetails`, `ClearedCartItems`) — register in `projections-inline.ts`, `projections-registry.ts`, and **`manual-rebuild-config.ts`**. After schema/handler changes or a fresh DB, run `pnpm rebuild:projections --all` ([PROJECTION_REBUILD_PLAN.md](../PROJECTION_REBUILD_PLAN.md)).
- **Order checkout status:** kiosk polls **`GET /api/orders/status`** (query: `cart_id`, `order_id`) until **Order Finished Details** or **Payment Failed Order** read models populate; no WebSockets in v0.1.
- **Checkout automations:** payment webhook → **`PayOrder` / `FailOrderPayment`**; **`OrderPaid`** triggers **`SellStockItem`**; all lines sold → **`FinishOrder`**; **`ClearCart`** → **`CartCleared`** → automator dereserves via **`RemoveItemFromCart`** + **`ClearedCartItems`** (sold lines skip dereserve). Diagram in [EVENT_MODEL.md](./EVENT_MODEL.md).

**Out of scope for now:** real payments, back-office menu admin, required Sentry/Axiom locally.
